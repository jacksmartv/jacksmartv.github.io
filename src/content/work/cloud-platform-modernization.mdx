## Problem

The platform had grown into a 200+ microservices environment running on infrastructure that was managed largely by hand. Deployments were slow and error-prone, incident response depended on tribal knowledge, and the lack of infrastructure as code made every environment subtly different from the next. None of this was sustainable at the scale the business was targeting.

## Constraints

- Multiple environments (dev, staging, production) had to stay in sync during the migration.
- Zero downtime was non-negotiable — this was a revenue-generating platform.
- No budget increase was available to fund the migration; it had to be absorbed by the existing team.
- The DevOps team consisted of 3 engineers, which ruled out any approach that required constant manual intervention.

## Decision

The migration was designed around three pillars:

1. **Infrastructure as Code first.** Every environment was rebuilt in Terraform before any workload moved, so the target state was reviewable and repeatable rather than tribal knowledge.
2. **Immutable, incremental deployments.** Services moved to Kubernetes one at a time behind existing traffic routing, so each migration step had an isolated blast radius and a clear rollback path.
3. **CI/CD as the single path to production.** Jenkins and GitLab pipelines became the only way to ship — removing manual deploys eliminated an entire class of configuration drift.

```mermaid
flowchart LR
    Dev[Developer Push] --> CI[Jenkins / GitLab CI]
    CI --> Build[Build & Test]
    Build --> IaC[Terraform Apply]
    IaC --> K8s[Kubernetes Cluster]
    K8s --> Monitor[Prometheus / Grafana]
```

### Trade-offs

Moving one service at a time was slower than a big-bang cutover, but it kept rollback cheap and made it possible to validate reliability improvements incrementally instead of betting the whole migration on a single cutover weekend.

## Result

- **32% reduction** in deployment time after standardizing the CI/CD pipeline.
- **30% reduction** in downtime, driven by consistent monitoring and incident response practices established alongside the migration.
- Zero unplanned outages attributable to the migration itself — every cutover had a tested rollback path.

## Lessons Learned

Infrastructure as Code pays for itself the first time an environment needs to be rebuilt from scratch, not the first time it's written. The biggest reliability gains came less from Kubernetes itself and more from the discipline the migration forced onto version control, monitoring, and incident management.
